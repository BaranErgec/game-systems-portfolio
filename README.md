## Project Overview

**Dünya** is a 2D isometric card-combat RPG built in Unity 6. The core loop blends **Slay the Spire–style deck construction** with **narrative branching via Yarn Spinner**, in a world where the same NPC interaction can resolve as a diplomatic negotiation, a street brawl, or a half-kept promise that haunts later encounters.

| Dimension | Detail |
|---|---|
| **Engine** | Unity 6 (URP) |
| **Language** | C# |
| **Dialogue** | Yarn Spinner 3.x |
| **View** | 2D Isometric, hand-crafted sprite layers (parallax + fog) |
| **Genre** | Rogue-lite / Card-combat / Narrative RPG |
| **Stage** | Playable prototype — combat loop, economy, save/load, and ~30 Yarn dialogue scripts functional |

## Architecture & System Design

### Dual State-Machine Approach

Combat and negotiation are intentionally **separate, parallel state machines**. Blending their HP/damage logic into a single manager was deliberately avoided during architecture review (Sept 2026).

```
┌─────────────────────────────────────────────────┐
│                  Yarn Spinner                   │  ← narrative glue / world-state owner
│   <<start_battle>>  <<start_negotiation>>       │
│   <<apply_negotiation_outcome>>  <<goto_node>>  │
└────────────┬──────────────────┬─────────────────┘
             │                  │
  ┌──────────▼──────┐  ┌────────▼────────────┐
  │CardBattleManager│  │ IletisimYoneticisi  │
  │  BattleState:   │  │  IletisimState:     │
  │  Inactive       │  │  Inactive           │
  │  PlayerTurn     │  │  PlayerTurn         │
  │  EnemyTurn      │  │  NpcTurn            │
  │  Resolution     │  │  Resolution         │
  └──────────┬──────┘  └────────┬────────────┘
             │                  │
  ┌──────────▼──────────────────▼────────────┐
  │            Shared Services               │
  │  OyuncuIlerlemesi (Deger/XP/Level)       │
  │  InventoryManager  (item state)          │
  │  NodeMapController (world graph)         │
  │  SaveManager       (ink-ribbon save)     │
  └──────────────────────────────────────────┘
```

### Node Map — Branch and Bottleneck

The world is a **directed graph of encounter nodes**, not an open map. Navigation is enforced by `NodeMapController`: a node transition is only permitted if the target `nodeId` appears in the current node's `sonrakiNodeIdler` list — otherwise the jump is silently rejected. Yarn scripts query current node state via registered `[YarnFunction]`s and issue their own `<<jump>>`, keeping the C# layer free of Yarn version assumptions.

```csharp
// NodeMapController.cs — enforced directional traversal
[YarnCommand("goto_node")]
public void GoToNode(string nodeId)
{
    if (!string.IsNullOrEmpty(mevcutNodeId))
    {
        NodeData mevcut = BulNode(mevcutNodeId);
        if (mevcut != null && !mevcut.sonrakiNodeIdler.Contains(nodeId))
        {
            Debug.LogWarning($"[NodeHaritasi] '{mevcutNodeId}' -> '{nodeId}' rejected (not in adjacency list).");
            return;
        }
    }
    // ... commit transition, mark visited
}
```

### Singleton Access Pattern — No FindObjectOfType in Hot Paths

Each runtime manager exposes a static `Aktif` property set in `Awake` / `StartBattle`. All cross-system calls use `ClassName.Aktif` or a guarded `Bul()` fallback — `FindObjectOfType` is reserved for editor-only setup paths, never called per-frame or per-card-play.

```csharp
// Consistent pattern across CardBattleManager, IletisimYoneticisi,
// NodeMapController, OyuncuIlerlemesi, SaveManager
public static CardBattleManager Aktif { get; private set; }

// Set at battle start, cleared at battle end — never stale
Aktif = this;   // StartBattle()
Aktif = null;   // ResolveBattleEnd() when state → Inactive
```

### Card Data — ScriptableObject Schema

`CardData` is a pure data container (ScriptableObject). Gameplay logic lives entirely in `CardBattleManager`; the schema carries no methods. This separation allows the 125-card library to be authored, balanced, and batch-generated by Editor scripts without touching game logic.

```
CardData
├── Identity:    cardName · description · cardId · illustrasyon (Sprite)
├── Combat:      baseDamage · maliyet · supheTur · silahBonusuUygulanir
├── Engines:     suphePerTur · borcBasinaHasar · supheTavaniAc · faizsiz
├── Typed FX:    isaretSuresiTur · isaretliBuyukHasar          (Imza_Gecikmeli)
│               savunmaAzaltmaYuzdesi · savunmaErtelemeYuzdesi (Imza_Savunma)
├── Taxonomy:    CardType · KartAlani · IknaTuru · AnaCapa
└── Persistence: TuketimTuru · kaliciDegerBonusu · geciciHasarBonusu
```

## Economic & Balance Philosophy

### Resource Architecture: Single Abstract Currency

The economy uses **one abstract resource — "Deger" (Value)** — rather than splitting into gold/honour/influence. The *form* of payment (coin, favour, cargo, a whispered name) is expressed narratively in Yarn; only the integer flows through C#. This prevents split-resource UI complexity while retaining narrative texture.

```
SOURCES                          SINKS
──────                           ─────
• Combat victory (zaferDegerOdulu)   • Merchant purchases (buy_item)
• Debt-recovery bonus XP             • Consumable card use
  (borcBasinaXpOdulu × intikam)      • Black-market barter (sadeceTakas items)
• Node loot                          • Save-file cost ("Tutulan Söz" item)
• Negotiation success bonus          • Equipment upgrade
```

### Sink/Source Integrity — The Ink-Ribbon Save

Saving the game costs **one "Tutulan Söz" consumable item** (Resident Evil ink-ribbon model). This is an intentional friction sink: the player must decide whether to spend a scarce resource or risk losing progress. A flag `ilkKayitUcretsizMi` (Inspector-configurable) gates a one-time free save for onboarding — deliberately left unresolved at design level, kept as a tuning knob.

### Revenge / Debt Loop (Loss Escalation Without Frustration)

Enemy move assets (`EnemyMoveData`) carry a runtime `intikamSeviyesi` counter that increments each time the player loses to that enemy — capped at `maxIntikamSeviyesi` (default: 3). Winning repays the debt and resets it. This creates a **self-balancing catch-up loop**: the enemy grows stronger proportionally to how many times the player has been beaten, but never becomes impossible.

```csharp
// EnemyMoveData.cs — runtime debt accumulation
public int intikamSeviyesi = 0;
public int maxIntikamSeviyesi = 3;
public int intikamHasarCarpani = 3; // flat damage added per level
// Applied in CardBattleManager.ResolveBattleEnd():
// intikamSeviyesi = Mathf.Min(intikamSeviyesi + 1, maxIntikamSeviyesi)
```

### Turn-1 Kill Ceiling — Simulation-Verified

The maximum theoretical T1 damage was formally verified with a Python simulation (`CardSim_v2.py`) reading real card values:

```
Worst-case T1: max(Normal.baseDamage) × turKartButcesi × 2.0 (damage-multiplier cap)
               = 9 × 3 × 2.0 = 54  <  60 HP  ✓  PASS
```

The `2.0×` cap comes from `GelenHasarCarpaniHesapla()` — individual chain bonuses stack **additively** (not multiplicatively) and are clamped with `Mathf.Min(total, 2.0f)`. Normal cards are hard-capped at `baseDamage ≤ 9`; high burst is reserved for `Imza_Gecikmeli` cards that require a prior setup card in an earlier turn (making them structurally impossible to resolve in T1).

### Negotiation → Combat Handoff — Staged Outcome Table

A resolved negotiation modifies the subsequent battle's starting conditions via a **pending-modifier pattern** — the outcome is written to `bekleyenMuzakereHpModifikatoru` and only applied when `StartBattle()` fires. Direct mutation of `playerHP` between `apply_negotiation_outcome` and `start_battle` was a documented bug; the pending-field pattern eliminates the silent-reset race condition.

| Negotiation Outcome (`SonDenge`) | Combat Effect |
|---|---|
| +1 to +4 (minor win) | `+kucukKademeHp` starting HP |
| +5 to +9 (major win) | `+buyukKademeHp` HP + enemy first-move weight penalty |
| -1 to -4 (minor loss) | `-kucukKademeHp` starting HP |
| -5 to -9 (major loss) | `-buyukKademeHp` HP + player first-turn budget reduced by 1 |

### Ana Çapa Zinciri — Combo Chain System

Five thematic "anchor" sets (Loss, Broken Vow, Betrayal, Fear/Escape, Injustice) each contain 25 cards. Playing **4+ cards of the same anchor in one turn** triggers a chain bonus. With a default budget of 3 cards/turn, chains are **structurally inaccessible T1** — they require a prior TutulmamışSöz chain bonus to unlock a 4th card slot, creating a two-turn setup requirement that rewards deck-building investment.

## Key Technical Highlights

### 1 — Yarn ↔ C# Command Bridge (Bidirectional)

Yarn scripts issue typed commands; C# exposes both `[YarnCommand]` handlers and `[YarnFunction]` query callbacks. The `negotiation_denge()` function was re-architected after hitting a `Yarn Spinner 3.2.8` bug where numeric arguments passed to `[YarnCommand]` via `Convert.ChangeType` silently raised `ArgumentOutOfRangeException`. Fix: read state from the C# manager directly rather than passing arguments through Yarn.

```csharp
// CardBattleManager.cs — argument-free command reads state from sibling system
[YarnCommand("apply_negotiation_outcome")]
public void ApplyNegotiationOutcome()
{
    IletisimYoneticisi ileti = IletisimYoneticisi.Bul();
    int sonDenge = ileti != null ? ileti.SonDenge : 0;
    KaydetMuzakereKademesi(sonDenge);  // writes to pending fields; never mutates HP directly
}
```

### 2 — Negotiation: Bidirectional Tension Meter

Unlike a simple "resistance bar", `IletisimYoneticisi` models negotiation as a **signed integer `denge`** (balance line) clamped between `±dengeSiniri`. The player pushes it positive; NPC counter-moves push it negative. Three card types have distinct mechanics:

```csharp
// IletisimYoneticisi.cs — Gözdağı (Intimidation) reverse-backfire logic
// gucKarsilastirmasi < 1.0: player disadvantaged → push can REVERSE direction
if (itisHesaplanan < gozdagiTersTepmeEsigi)
{
    denge -= Mathf.RoundToInt(itisHesaplanan); // pushes TOWARD NPC, not player
}
```

### 3 — Enemy AI: Weighted Move Selection + Telegraph

Enemy moves are ScriptableObject assets with a `weight` field. Each turn, `AgirlikliHamleSec()` performs weighted random selection over the `enemyMoves` list. The selected move is **telegraphed one turn in advance** — surfaced to the player via `TelegraphMetni()` so they can plan a defensive response:

```csharp
// EnemyMoveData.cs — telegraph string, type-dispatched
public string TelegraphMetni() => type switch
{
    MoveType.Blok      => $"{moveName} (enemy gains {damage} block)",
    MoveType.Gecikmis  => $"{moveName} ({damage} damage — arrives in 2 turns)",
    MoveType.Karsilik  => $"{moveName} ({damage}% of your damage reflected)",
    MoveType.AgirDarbe => $"{moveName} ({damage} dmg, enemy takes {geriTepme} recoil)",
    _                  => $"{moveName} ({damage} damage)"
};
```

### 4 — Signature Card Combo (Setup → Payoff)

`Imza_Kurulum` ("Mark") cards apply a `isaretKalanTur` counter. A subsequent `Imza_Gecikmeli` ("Collect") card checks this counter and deals `isaretliBuyukHasar` (large damage) instead of `baseDamage` (small damage), consuming the mark. This creates a two-card setup/payoff tempo mechanic:

```csharp
// CardBattleManager.cs — mark-check in KartEtkisiUygula()
if (playedCard.type == CardType.Imza_Gecikmeli)
{
    if (isaretKalanTur > 0)
    {
        temelHasar = playedCard.isaretliBuyukHasar;  // big hit
        isaretKalanTur = 0;                          // mark consumed
    }
    // else: baseDamage (small hit, mark was absent or expired)
}
```

### 5 — Save System: State Serialisation Without a Database

`SaveManager` serialises five distinct subsystems to a single JSON file with no external persistence library:

- `NodeMapController`: current node ID + visited set
- `OyuncuIlerlemesi`: Deger / XP / Level (volatile combat state excluded by design)
- `InventoryManager`: per-item `(itemName, durum, devredildigiKisi)` triples
- `Yarn InMemoryVariableStorage`: all `$variable` world-flags via `GetAllVariables()` / `SetAllVariables()`

Transient battle state (`aktifGeciciHasarBonusu`, chain counters) is deliberately **not** serialised — these are mid-battle ephemera, not narrative state.

### 6 — Yarn Dialogue Extract: Three-Way Moral Branch

The `XenakhKontrati.yarn` script demonstrates the state-tracking pattern: three NPCs must each be queried before the decision node unlocks, preventing players from resolving the contract without narrative context. Each outcome sets distinct Yarn variables consumed by downstream nodes:

```yarn
// XenakhKontrati.yarn — guarded decision gate
title: SertSecim
---
<<if not $nobetci_konustu or not $xenakh_konustu or not $nurkadaq_konustu>>
    (You haven't learned enough yet. Talk to all three.)
    <<stop>>
<<endif>>
-> Support Xenakh's unofficial seal.
    <<give_card SavasYoneticisi "gayri_resmi_muhur">>   // reward: card added to deck
    <<set $kontrat_xenakh_sonuc = "hizli_tartismali">>
-> Request an official committee. (slow, clean)
    <<give_card SavasYoneticisi "resmi_hukum">>
    <<set $itibar_xenakh = "reddedildi_resmi_onaylandi">>
-> Refuse. Leave it unresolved.
    <<set $yarim_kalan_vaat_xenakh = true>>             // haunts later encounters
===
```
